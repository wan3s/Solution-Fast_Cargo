# 1. Выгоды бизнеса

* Масштабируемость приведет к тому, что бизнес будет готов обрабатывать в 10 раз больше заказов => многократное увеличение прибыли. 
* За счет повышения минимального порога доступности до 99,95% система будет не доступна не более 4 часов 23 минут в год. То есть потеря из-за простоя прибыли не большая. 
* Стабильность при обработке высоконагруженных потоковых данных позволит не терять и не отставать в обработке данных с датчиков телематики. То есть информация по любой машине всегда будет доступна. Прозрачность вызывает больше доверия у клиентов => потенциально может появиться ещё больше новых клиентов.
* Соответствие требованиям ФЗ-152 о защите персональных данных убережёт бизнес от штрафов и санкций со стороны регуляторов.
* Соответствие стандартам PCI DSS снизит риск репутационных потерь при утечке данных.

# 2. Базовая и целевая архитектура

## AS-IS

Основные антипаттерны такие:
* Размытие ответственности в слое BFF - из-за единой кодовой базы любые правки в коде личного кабинета могут негативно сказаться на приложении курьеров.
* Общая база данных. Это, наверное, самый главный антипаттерн. Сервисы не должны пользоваться общей БД: если базе станет плохо, перестанет работать вся система.
* Низкая отказоустойчивость интеграционного шлюза - сбои в СУБД приводят к ошибкам при взаимодействии с платёжными системами. Шлюз не дожидается ответа от банка и падает.
* Высокая связность кода из-за монолита. Невозможно параллельно и независимо деплоить разные участки системы, тк они связаны друг с другом.

## TO-BE
В целевой картине указанные выше пункты стоит исправлять следующим образом:
* Разделить слой BFF по сервисам (приложениям), которые с ним взаимодействуют.
* Разделить базу данных на несколько (где это возможно), либо поставить отдельный сервис, который единственный будет взаимодействовать с базой напрямую, а все остальные сервисы при необходимости сходить в базу будут идти через этот сервис.
* Асинхронно записывать в базу статус платежа (например, через Кафку), чтобы проблемы в СУБД не фейлили работу с платеэными системами.
* Разделить монолит на микросервисы.
